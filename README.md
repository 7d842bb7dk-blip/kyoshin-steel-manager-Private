# 鋼材管理システム（Kyo-shin Steel Manager）

鋼材の **在庫検索 / 在庫管理 / 重量・材料費の計算** を行う社内向けの Web アプリです。
元になった Excel（`新_鋼材管理Excel.xlsm`）の計算ロジックを忠実に再現しており、
10 件の計算行はすべて Excel と重量が一致することを確認済みです。

使い方は 2 通りあります。
- **社内共有サーバー版（推奨）** … 1 台の PC でサーバーを動かし、全 PC がブラウザで同じ URL にアクセス。在庫データを全員で共有します（下記「0.」）。
- **単体版（オフライン）** … `dist/鋼材管理システム.html` を各 PC で開く。データはその PC のブラウザ内（localStorage）に保存され、PC 間では共有されません。

---

## 0. 社内共有サーバー版（全PCで在庫を共有）★推奨

在庫データを 1 か所に集約し、社内のどの PC からでも同じ最新データを見る／編集できます。
追加・編集は数秒で全 PC に反映されます（自動同期）。

- **アクセス URL**：`http://192.168.1.107:3001/` （同一 LAN の PC・スマホから。お気に入りに登録してください）
- **稼働ホスト**：社内 PC（`PROGRAM-TSUJIMOTO` / 192.168.1.107）。`program-load-board`（:3000）と同じ PC で別ポート **:3001**。Server-01・CIPS には影響しません。
- **自動起動**：この PC のログオン時に `スタートアップ\kyoshin-steel.vbs` がサーバーを隠しで起動します（普段の手動操作は不要）。
- **構成**：`server/index.js`（Express）＋ `server/db.js`（SQLite `server/data/app.db`）。フロント（`index.html`/`styles.css`/`js/app.js`/`assets/`）はこのサーバーが配信します。
  クライアントは起動時に `/api/health` を確認し、サーバー配信なら **共有モード**（REST API ＋約 5 秒ポーリングで全 PC 同期）、`file://` で開いた場合は従来の **localStorage モード** に自動で切り替わります（同じ `js/app.js` が両対応）。
- **データの保存場所**：`server/data/app.db`（稼働 PC のローカルディスク）。**バックアップ**は「在庫管理 → CSV出力」、または `app.db` のコピーで取得します。
- **既存データの移行**：各 PC のブラウザに入れていた在庫は、その PC で「CSV出力」→ 共有サーバーで「CSV取込」で移せます。
- **セットアップ／再起動**（メンテナンス時のみ。稼働 PC の `kyoshin-steel-manager` フォルダで）：
  ```powershell
  npm install                 # 初回のみ（依存パッケージの取得）
  # 本番起動（隠しコンソール・作業セッションから独立）
  wscript "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\kyoshin-steel.vbs"
  ```
  ※ 稼働中はネットワーク共有上ではなくローカルディスクで動かします（SQLite の安定動作のため）。
  共有フォルダ（`\\Server-01\…\kyoshin-steel-manager`）は原本・バックアップとして維持します。

## 1. 動かし方（単体版・開発用）

### そのまま使う（配布用・1ファイル版）
`dist/鋼材管理システム.html` をダブルクリックしてブラウザで開くだけです。
CSS・JavaScript・ロゴをすべて 1 ファイルに埋め込んであるため、これ単体で動作します。
（`dist/` が無い場合は「3. ビルド」を実行してください）

### 開発しながら使う（ソース版）
`index.html` をブラウザで開きます。`styles.css` / `js/app.js` / `assets/logo.png` を
相対パスで読み込みます。多くのブラウザはファイルを直接開いて動作しますが、もし
読み込みがブロックされる場合は、フォルダ内で簡易サーバーを起動してください：

```bash
python -m http.server 8000
# → ブラウザで http://localhost:8000/ を開く
```

## 2. ファイル構成

```
kyoshin-steel-manager/
├── index.html          画面のマークアップ（CSS/JSは外部ファイルを参照）
├── styles.css          スタイル（デザイン・配色・レイアウト）

│   └── logo.png        Kyo-shin ロゴ（背景透過 PNG）

├── CHANGELOG.md        変更履歴
└── README.md           このファイル
```

ロジックとデータは `js/app.js` に集約しています。ファイル冒頭のコメントに、
よく編集する設定・マスタの一覧と、それぞれの場所の目印を記載しています。

## 3. ビルド（1ファイル版の生成）

`index.html` / `styles.css` / `js/app.js` / `assets/logo.png` を 1 つの自己完結型
HTML にまとめます。依存ライブラリは不要です。

```bash
python build.py
# → dist/鋼材管理システム.html が生成されます
```

ソース（上記4ファイル）を編集したら、この `build.py` を再実行して配布用の
1ファイル版を作り直してください。

## 4. よくある編集（マスタ・設定の変更）

いずれも `js/app.js` の冒頭付近にある定数を書き換えます。

| 変更したいこと | 編集する定数 | 例・補足 |
|---|---|---|
| 材質を追加・変更 | `MATERIALS` | `["SS400","SUS304",...]` |
| 鋼種（形状）の選択肢 | `KOSHU_BY_MAT` | 材質ごとに配列で指定 |
| 材料規格（寸法）の候補 | `KIKAKU_BY_KOSHU` | 鋼種ごとに配列で指定 |
| 表面仕上げの候補 | `FINISH_ALL` / `FINISH_BY_MAT_KOSHU` | 後者は「材質\|鋼種」単位で上書き |
| 板厚の候補 | `THICKNESS` | 数値の配列 |
| 保管場所 | `LOCATIONS` | 文字列の配列 |
| 比重 | `DENSITY` | 材質名→比重。未登録材質は SUS 系=7.93／他=7.85 で代用 |
| キロ単価のルール | `SUS_PRICED` / `PRICE` | 詳細は `docs/CALCULATION.md` |
| 断面積計算式の説明文 | `FORMULA_DESC` | マスタ参照画面の表示用 |
| 初期データ（サンプル在庫） | `SEED` | 初回起動時に読み込む在庫 |
| 管理者パスコード | `ADMIN_PIN` | 既定値 `"1234"`。必ず変更してください |

### ロゴを差し替える
`assets/logo.png` を新しい画像に置き換えるだけです（縦横比は自由、ヘッダーでは
高さ 34px で表示）。1ファイル版に反映するには `build.py` を再実行します。

### 配色（赤・黒など）を変える
`styles.css` 冒頭の `:root { --accent: ...; }` などの CSS 変数を変更します。
`--accent` がブランドの赤、`--strip` 系がヘッダーの黒です。

## 5. 機能の概要

- **在庫検索** … 材質→鋼種→規格などで絞り込み（空欄はすべて対象、材料規格は部分一致）。
  ヒット件数・合計重量・合計金額を集計し、CSV 出力可。
- **在庫管理** … 在庫の追加・編集・削除。重量／キロ単価／材料費は自動計算。
  CSV 取込／出力に対応（UTF-8 BOM 付きで Excel と相性良）。
- **重量・単価計算** … 単品の試算。断面積・重量・比重・キロ単価・材料費と適用式を表示。
- **マスタ参照** … 比重・キロ単価ルール・断面積式・規格候補の一覧。
- **管理者モード** … 「重量・単価計算」「マスタ参照」はパスコード入力時のみ表示。
- **使い方ガイド** … ヘッダーの「使い方」ボタン、または `?` キーで表示。

## 6. データの保存について

- 在庫データはブラウザの **localStorage**（キー `steel_mgr_records_v1`）に自動保存されます。
- **同じブラウザ・同じ端末でのみ保持**され、別の PC やブラウザには引き継がれません。
- バックアップ・移行は「在庫管理 → CSV出力」で行ってください。
- ブラウザのデータ消去（履歴クリア等）を行うと在庫データも消えます。

> 本格的な複数人・複数端末での共有が必要になった場合は、サーバー側
> （DB ＋ API）の導入が必要です。「8. 今後の拡張」を参照。

---

## 7. 動作環境

- 最新版の Chrome / Edge / Firefox / Safari を想定。
- インターネット接続は不要（外部 CDN・フォント・API への通信なし）。
- 丸ゴシック系フォント（Hiragino Maru Gothic / M PLUS Rounded 等）が端末にあれば
  自動で適用され、無い場合は標準ゴシックで表示されます。

## 8. 今後の拡張のヒント（引き継ぎメモ）

- **データの共有/永続化**：localStorage → サーバー API（例：FastAPI / Express ＋ SQLite/PostgreSQL）。
  `loadRecords()` / `saveRecords()` を API 呼び出しに差し替えるのが入口。
- **認証**：現在の管理者モードはクライアント内の簡易ロック（ソースを見ればコードが分かる）。
  実運用で保護が必要ならサーバー側認証へ。
- **マスタの外部化**：`MATERIALS`〜`PRICE` などを JSON 化し、`fetch` で読み込む構成にすると
  非エンジニアでも編集しやすくなります（その場合はサーバー or 開発サーバー経由で実行）。
- **テスト**：`docs/CALCULATION.md` の式と Excel の値を突き合わせる単体テストを追加すると安全。
- **ビルド**：規模が大きくなる場合は Vite 等のバンドラ導入を検討（現状は依存ゼロ運用）。

## 9. 計算ロジック

断面積・重量・キロ単価・材料費の計算仕様は **`docs/CALCULATION.md`** にまとめています。
Excel の挙動（とくにキロ単価の合算ロジック）を再現しているため、式を変更する際は
必ず一読してください。
